# 报价工作台使用与维护

这版报价工作台接在现有项目的 `/quotes` 中。Excel 导入、物料编辑、工时费用、保存、版本恢复及 Excel 导出使用真实后端；历史价格库、店小二、采购协同均未接入。

## 打开

双击项目根目录的 **启动报价工作台.cmd**。需先启动 Docker Desktop；本机 Node.js 已具备。启动器会检查依赖、启动独立数据库，缺少前端构建时自动构建，然后打开 `http://127.0.0.1:5271/quotes`。

开发时在根目录执行：

```powershell
npm install
npm run db:up
npm run dev
```

开发页面使用 `http://127.0.0.1:5273/quotes`；常规使用为 5271。源码更新后运行 `npm run build`，重新启动本项目后端。其他项目的容器、服务和数据不需要重启。

## 一份报价的操作

1. 新建报价，填写客户、项目等信息。
2. 导入 `.xlsx`。原报价模板可恢复柜型、工时和费率；普通客户清单需检查表头、列对应、起止行与工作表选择。多工作表可一起导入，选择“所属柜型”列可按柜型分组。
3. 确认清单数量口径：**每台用量**或**此柜型整单用量**。柜型数量另填；工时、辅材、柜体等费用始终按单台填写。口径不清楚可先保存为草稿。
4. 可以直接编辑表格、添加物料、勾选后批量删除 / 复制 / 改单价 / 改价格状态。批量粘贴按界面列顺序接收制表符分隔的 Excel 数据。
5. 在“工时与费用”页填写成套、检验、调试工时及单价，填写其他费用、管理费率、税费率与利润率。
6. 修改停顿后自动保存到数据库，也可点击“保存”或按 Ctrl+S。页面显示保存成功及版本号。保存失败时编辑保留在当前页，本机恢复副本作为辅助保护；数据库仍是正式保存位置。
7. 点击“导出 Excel”。系统先保存当前编辑，再导出对应版本的“总清单”和“电控柜主材明细”，包括全部柜型和有效公式。

导出的是**含材料成本、工时、费率和内部备注的报价计算表**，不是隐藏成本的对客简版。它重新生成表格，保留算法及数据字段，不承诺复刻原文件中的图片、公司抬头、所有排版或宏。原文件保持不变。

## 固定的计算口径

定义每台材料费为 M、柜体费为 C、其他费用合计为 O。O 包括辅材、标牌、运费、包装、成套、检验、调试，不包含柜体。

| 项目 | 公式 |
|---|---|
| 材料明细金额 | 单台用量 × 单价 |
| 成套 / 检验 / 调试费 | 工时 × 对应时薪 |
| 管理费 | (M + O) × 管理费率 |
| 税费 | O × 税费率 |
| 利润 | (M + O) × 利润率 |
| 单台报价 | M + C + O + 管理费 + 税费 + 利润 |
| 不含税价 | 单台报价 ÷ 1.13 |
| 最终优惠价 | 等于单台报价，沿用原表 |
| 整单报价 | 各柜型完整精度单台报价 × 柜型数量，再求和 |

费率在界面以百分数填写，默认管理费 4%、税费 3%，利润留空等效 0。人工单价默认 35 元 / 小时。没有把 13% 另加到整单，也没有把工时备注中的数字再计入费用。

金额使用十进制计算和字符串保存，中间过程不按显示金额舍入；界面保留两位小数。Excel 使用自身的浮点数计算，可能在极小尾数上存在差异，最终按分显示一致。计算规则版本为 `jn-original-20261014-v1`。

## 状态与来源

- 空白单价保留“待定价”；试算按空值零参与，但不会因此被标为已确认。
- 普通客户清单中的价格默认不采用。勾选采用后仍标为“待确认”，不会自动当作采购成本。
- 修改单价会回到待确认；“客户供料”和“不计价”在选择时将当前价格设为 0，原始导入值保留在来源记录中。
- 可分别保存价格来源、价格口径、价格日期、交期、客户备注和内部备注。价格口径只作记录，不自动换算税价。
- 点击“原表第 N 行”可查看原始文件名、工作表、行号和导入值。
- 未完成核价或未确认数量口径的报价可保存，导出标题标为草稿。

## 版本与冲突

每次成功保存生成快照。“版本记录”可恢复旧内容为新版本，现有版本保留。两个窗口修改相同版本时，后保存的一方会收到冲突提示，不覆盖已保存数据。可以另存副本，或重开最新版本后人工合并。

列表中的删除是软删除；历史仍在本项目数据库中。当前没有回收站界面。报价列表显示最近 500 条，版本窗口显示最近 100 次保存；数据库保留其余记录。

## 数据位置和边界

本机实际使用 **MariaDB 11.8.9**，通过 `mysql2` 使用 MySQL 协议。采用已有的官方数据库镜像建立独立实例，因为 MySQL 8.4 镜像下载未能及时完成。业务表及 JSON 读写兼容 MySQL 8；尚未在 MySQL 8 实例进行实测。

| 资源 | 配置 |
|---|---|
| 应用 | `127.0.0.1:5271` |
| 开发前端 | `127.0.0.1:5273` |
| 数据库 | `127.0.0.1:33371`，库名 `jingneng_workbench` |
| Compose 项目 | `jingneng-quote-workbench` |
| 数据卷 | `jingneng-quote-workbench_quote-data` |
| Docker 子网 | `10.253.71.0/24`，单独设置以避开本机默认地址池耗尽的问题 |
| 本机配置 | `.local/workbench/mysql.env`，首次随机生成密码，不进入 Git |
| 原始上传 | `.local/workbench/uploads/` |
| 后端日志 | `.local/workbench/server.log` 和 `server-error.log` |

数据库和应用只监听本机。该版本没有多人登录、角色权限或局域网发布；现有项目的其他页面仍是原演示模块，已显示演示标识。

`npm run backup` 会在 `.local/workbench/backups/时间戳/` 生成一致的数据库 JSON 快照及上传文件副本，不包含密码。它是额外备份，不替代正式的数据卷备份策略。恢复目前需维护人员操作，尚无恢复向导。

导入限 `.xlsx`，单文件不超过 12 MB；最多 50 个工作表，每表 10000 行 / 200 列；每柜型最多 5000 条物料，单报价最多 100 个柜型。物料界面每页显示 100 行。`.xls`、宏、PDF、图片清单及任意复杂异形表格不在本版范围内。含公式的客户文件只读取已保存结果，请在 Excel / WPS 中重算并保存后导入。

## 验证命令

```powershell
npm run build
npm test
$env:RUN_DB_TESTS = '1'
npm test
npm run verify:reference -- '原报价Excel的绝对路径'
```

数据库集成测试仅对自己新建的“自动验收临时数据”操作，结束后软删除测试记录。原表验算会检查输入文件哈希、147 个数值 / 引用位置、导出回读一致性，结果在 `.local/workbench/reference-verification.json`。浏览器验收截图和下载文件位于被 Git 忽略的 `output/playwright/`。
