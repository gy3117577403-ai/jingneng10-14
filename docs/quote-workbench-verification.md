## 自动化与数据库

`npm run build`：前端生产构建、后端 TypeScript 检查通过。

`RUN_DB_TESTS=1 npm test`：**11 项测试全部通过**，包括以下有业务意义的边界：

- 柜体不进入管理费、税费、利润的计费基数，材料不进入原表税费基数。
- 整单物料用量仅折算一次；单台人工按柜数汇总。
- 不在材料行或柜型单价处提前舍入。
- 缺价、零元、空白利润、工时说明分别处理。
- 多工作表、柜型分组、隐藏行排除、前导零、备注、交期和来源保留。
- 动态导出公式、空柜型、全部柜型打印范围、导出再导入。
- 实际数据库的保存重读、重复保存请求幂等、旧版本冲突、无效数字拒绝、版本恢复、导出版本检查和软删除。

后端服务实际停止后重启，原表验收样例仍是版本 8、3 个柜型、81 行物料，成套工时为恢复后的 44 小时。

`npm run lint --workspace frontend`：无错误；剩余 7 条警告来自现有演示页面、共用 UI 组件和原布局。新增工作台文件没有 lint 警告。

## 实际浏览器操作

通过独立 Playwright 浏览器会话操作页面，使用真实后端，没有用 mock 响应替代：

1. 新建报价、填写客户、上传用户原 Excel，识别出 3 个柜型与 81 行物料并导入。
2. 成套工时从 44 改为 45，整单工时从 71 变为 72；金额从 33679.238 变为 33716.688，增加 37.45 元。刷新后编辑仍在。
3. 新增物料，填写带前导零的型号、小数单价、数量和备注，改数量、删除物料，金额分别重算。
4. 从版本记录恢复原始金额；点击页面“导出 Excel”，实际下载包含两个工作表的文件。
5. 导入生成的普通客户测试清单，确认表头第 3 行、列对应、柜数 2 和整单用量；合计行跳过，单价采用后为待确认，空白单价仍缺价。
6. 390×844 手机尺寸下完成导入、填价格、保存。页面宽度保持 390，物料表格在内部横向滚动。
7. 复制与删除柜型、批量粘贴两行物料均完成，备注、交期和缺价状态保留。
8. 模拟另一窗口先保存，当前窗口保存收到 HTTP 409，编辑内容保留；“另存为新报价”成功保存当前未保存的型号。
9. 最后正常流程的浏览器控制台没有错误或警告。冲突测试期间出现的 409 是预期保护响应，已单独核实。
