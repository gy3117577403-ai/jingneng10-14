# 京能协同平台 · 数据字典

> 面向后端实现者（Codex）。与 `schema.sql` 一一对应；SQL 中的中文 COMMENT 为准，本字典补充业务语义、枚举与状态机。
> 全局约定：所有查询必须带 `deleted_at IS NULL`；金额 `DECIMAL(14,2)`；时间 `DATETIME`（存北京时间）；`id` 统一 `BIGINT UNSIGNED` 自增。

---

## 一、全局枚举与状态机

### 1.1 报价单据状态（quotes.doc_status）

| 值 | 中文 | 说明 |
|---|---|---|
| draft | 草稿 | 新建未提交，可任意编辑/删除 |
| pending | 待审批 | 已提交，审批流转中；单据锁定不可编辑 |
| approved | 已批准 | 审批通过，可执行"转订单" |
| rejected | 已驳回 | 审批驳回，可退回草稿重新提交 |
| ordered | 已转订单 | 已转入订单（ERP），终态，不可再改 |

**状态机（只允许以下流转）：**

```
draft ──提交审批──▶ pending ──审批通过──▶ approved ──转订单──▶ ordered
                      │                      （终态）
                      ├──审批驳回──▶ rejected ──重新提交──▶ pending
                      │                    │
                      └──审批人退回────────┘
draft ──删除──▶ (逻辑删除)
```

### 1.2 报价审批状态（quotes.approval_status）

| 值 | 中文 |
|---|---|
| none | 未提交 |
| pending | 审批中 |
| approved | 已通过 |
| rejected | 已驳回 |

由后端在审批动作时与 `approvals.status` 联动更新，禁止前端直接写。

### 1.3 审批单状态（approvals.status）

| 值 | 中文 | 流转 |
|---|---|---|
| pending | 审批中 | → approved / rejected / cancelled |
| approved | 已通过 | 终态 |
| rejected | 已驳回 | 终态 |
| cancelled | 已撤回 | 终态（申请人撤回后可重新提交，生成新审批单） |

### 1.4 审批动作（approval_records.action）

| 值 | 中文 | 说明 |
|---|---|---|
| submit | 提交 | 申请人提交，step_no=1，生成时间线起点 |
| approve | 通过 | 当前节点通过；若为末节点则审批单→approved |
| reject | 驳回 | 审批单→rejected，单据→rejected |
| return | 退回 | 退回上一节点或申请人（本期实现为退回申请人，单据→rejected，可重提） |
| cancel | 撤回 | 仅申请人、仅 pending 状态可撤回 |

### 1.5 其它枚举

| 表.字段 | 值 | 中文 |
|---|---|---|
| users.status | 1 / 0 / 2 | 正常 / 停用 / 锁定 |
| departments.status, roles.status, apps.status, materials.status, cabinets.status, process_fees.status | 1 / 0 | 启用 / 停用 |
| materials.unit | ton / sheet / meter | 吨 / 张 / 米 |
| materials.tax_included | 1 / 0 | 含税价 / 未税价 |
| process_fees.charge_type | per_area / per_piece / per_meter / fixed | 按面积 / 按件 / 按米 / 固定一口价 |
| notifications.type | approval / mention / system | 审批 / @我 / 系统 |
| attachments — biz_type | quote / approval / app_drawing / … | 业务类型，见 3.4 |

## 二、单号规则（应用层生成）

| 单据 | 规则 | 示例 |
|---|---|---|
| 报价单号 quotes.quote_no | `Q` + `YYYYMM` + 4位月内流水（不足补0） | Q2026100001 |
| 材料编码 materials.material_code | 材质缩写 + `-` + 规格，如 `STL-CR-2.0` | STL-CR-2.0 |
| 箱柜型号 cabinets.cabinet_no | 系列前缀 + 规格，如 `XG-2000` | XG-2000 |

**并发安全**：报价单号禁止"先查最大再+1"。实现方式二选一（推荐①）：
1. 单独序列表 `sequences(biz_key, curr_val)`，用 `UPDATE … SET curr_val = LAST_INSERT_ID(curr_val+1)` 原子取号；
2. Redis `INCR quote:seq:202610`。
月度切换时流水重置（key 带 YYYYMM 即可天然重置）。

## 三、表明细

### 3.1 departments — 部门表（树形）

- **用途**：组织架构；通讯录按树展示；用户归属部门。
- **关键字段**：`parent_id` 上级部门（NULL=根）；`leader_user_id` 负责人（**不建外键**，避免与 users 循环引用，应用层校验存在性）。
- **索引**：`uk_code` 编码唯一；`idx_parent` 按父查子。
- **种子数据**：根部门"浙江京能电力设备"下挂钣金车间/成套车间/质检部/销售部/技术部/行政部。

### 3.2 users — 用户表

- **用途**：登录、业务员、审批人、评论人等所有"人"的唯一来源。
- **关键字段**：`username` 登录名唯一；`password_hash` 只存哈希（bcrypt/argon2），**禁止明文**；`employee_no` 工号唯一可空；`status` 1=正常/0=停用/2=锁定。
- **索引**：`uk_username`、`uk_employee_no`、`idx_dept`。

### 3.3 roles / 3.4 user_roles — 角色与关联

- **用途**：RBAC。`roles.code` 约定：`admin`=系统管理员，`salesman`=业务员，`approver`=审批人。
- `user_roles` 联合唯一 `(user_id, role_id)`，防重复授权。

### 3.5 apps — 应用注册表（平台插件化核心）

- **用途**：平台可插拔应用清单。**前端侧边栏菜单从此表动态渲染**，新应用上线只需 INSERT 一行。
- **关键字段**：`code` 全局唯一（`quote`/`price`/`drawing`/`quickquote`），同时是**新表名前缀**（`app_{code}_*`）和**前端路由段**（`/app/{code}`）；`status`=0 的应用不在菜单显示（如图纸分解、快速报价，待上线）。
- **索引**：`uk_code`；`(status, sort)` 供菜单查询。

### 3.6 app_permissions — 应用权限点

- **用途**：细粒度权限，如 `quote:approve`。角色与权限点的绑定关系建议后端另建 `role_permissions` 表（本期可先在代码中按角色硬编码映射，后续再表化——见接入规范）。
- 联合唯一 `(app_id, perm_code)`。

### 3.7 quotes — 报价单表

- **用途**：报价管理核心单据。
- **金额三段式**：`subtotal`（未税小计=明细金额之和）→ `tax_amount`（税额=小计×税率）→ `total_amount`（价税合计）。**由后端计算，前端只展示**；明细变更时重算。
- **双状态**：`doc_status` 单据状态（见 1.1 状态机）+ `approval_status` 审批状态（见 1.2），后端联动，禁止前端直写。
- **索引**：`uk_quote_no`；`idx_customer` 客户模糊查；`idx_doc_status` 状态筛选；`idx_salesman`；`idx_created` 时间排序。

### 3.8 quote_items — 报价明细表

- **用途**：报价单行项。`line_no` 同单内唯一（联合唯一）。
- **价格库联动**：`cabinet_id` / `material_id` 为空=手工录入；非空=从价格库引用（快速报价场景），此时 `unit_price` 建议取价格库核算价快照写入（**快照原则**：历史单据不随价格库调价而变）。
- 外键 `quote_id → quotes` 用 `ON DELETE CASCADE`（删单带走明细；实际业务中已提交单据禁止删除，用逻辑删除）。

### 3.9 approvals — 审批单表（通用）

- **用途**：所有应用共用一套审批流。`biz_type`+`biz_id` 定位业务单据，联合唯一（一单一审）。
- **约定**：`biz_type='quote'` 表示报价单；后续应用如图纸分解用 `biz_type='app_drawing'`。
- 审批节点人选由后端按 `total_steps` 与业务规则确定（如 step1=技术部负责人，step2=总经理）；本期节点规则可先配置化在代码常量中。

### 3.10 approval_records — 审批记录表（时间线）

- **用途**：只追加不修改，完整留痕。`submit` 由申请人产生；每条记录即时间线一个节点。
- **索引**：`(approval_id, step_no)` 按审批单查时间线。

### 3.11 quote_comments — 报价协同评论表

- **用途**：报价单下的协同留言。`mention_user_ids` JSON 数组存被@用户ID，后端解析后写 `notifications`（type=mention）。
- 外键 `quote_id → quotes` 用 `ON DELETE CASCADE`。

### 3.12 attachments — 附件表（通用）

- **用途**：`biz_type`+`biz_id` 挂靠任意业务（`quote`=报价单附件，`approval`=审批附件，`app_drawing`=图纸文件…）。`file_path` 存对象存储 key 或相对路径，**不存 base64**。
- **索引**：`(biz_type, biz_id)`。

### 3.13 notifications — 通知表

- **用途**：站内信。`link_url` 约定为前端路由（如 `/app/quote/detail/12`），点击直达。
- **写入时机**：审批提交/通过/驳回（type=approval，接收人=下一节点审批人/申请人）、评论@（type=mention）。
- **索引**：`(user_id, is_read)` 未读数查询；`idx_created`。

### 3.14 materials — 材料库

- **用途**：价格库·物料。`grade` 材质牌号（如冷轧板/镀锌板/304不锈钢/铝板/紫铜板）；`thickness_mm` 厚度；`density` 密度（钢 7.85 / 铝 2.70 / 铜 8.90，单位 kg/(m²·mm)）；`price` 按 `unit` 计价（吨价即元/吨）。
- **调价**：更新 `price` 时必须同步写 `material_price_history` 一条（后端事务保证）。
- **索引**：`uk_material_code`；`idx_grade` 按牌号筛选。

### 3.15 material_price_history — 材料调价记录表

- **用途**：价格变更审计。只追加。`changed_at` 默认为写入时间。

### 3.16 cabinets — 箱柜库

- **用途**：价格库·箱柜。`cabinet_no` 型号唯一（如 XG-2000）；`width/depth/height_mm` 箱规三维；`spec_desc` 箱规文字描述（如"2000×800×600落地式"）。

### 3.17 cabinet_bom — 箱柜BOM明细表

- **用途**：箱柜→部件→材料的两层结构核心。`area_m2` 展开面积，`thickness_mm` 冗余自材料（BOM 可独立调整厚度而不改材料字典），`quantity` 单台件数，`loss_rate` 损耗率。
- **成本公式**（前后端统一，前端实时计算、后端在"引用到报价"时计算快照）：
  ```
  部件单重(kg) = area_m2 × thickness_mm × density
  部件材料成本(元) = 单重 / 1000 × quantity × (1 + loss_rate) × materials.price（元/吨）
  ```
- 外键 `cabinet_id → cabinets` 用 `ON DELETE CASCADE`。

### 3.18 process_fees — 加工费用项字典

- **用途**：激光切割/折弯/焊接/表面处理/组装等费用项，可扩展。`charge_type` 决定 `charge_param` 的含义（见 3.19）。
- **种子数据**：5 项常用费用（示例单价，投产前按实际核定）。

### 3.19 cabinet_process_fees — 箱柜加工费用明细表

- **用途**：某箱柜实际发生的加工费用。`charge_param` 按 `charge_type` 理解：per_area=m²数，per_piece=件数，per_meter=米数，fixed=1；`amount` = 计价参数 × 费用项单价（**冗余存储**，费用项日后调价不追溯历史箱柜成本）。
- 联合唯一 `(cabinet_id, fee_id)`。

### 3.20 operation_logs — 操作日志表

- **用途**：审计。`module`+`action`+`biz_type`/`biz_id` 定位动作；`detail` JSON 存前后值等扩展信息；`user_id` 可空（系统定时任务）。
- **索引**：`(user_id, created_at)`、`(module, created_at)`。
- **写入建议**：登录、报价新建/提交/审批/转订单、材料调价、BOM 变更必须记；查询类不记。

## 四、与旧版钣金价格库概念的对齐

| 旧版UI概念 | 本设计对应 | 说明 |
|---|---|---|
| 物料库（8种板材价） | `materials` | 牌号/厚度/单价·元/吨一致；新增密度、含税标记、来源、调价记录 |
| 箱柜库（5个箱柜） | `cabinets` | 型号/箱规一致；宽深高拆为三字段便于筛选 |
| 箱柜详情=BOM明细 | `cabinet_bom` | 部件/材料/展开面积一致；成本公式"面积×厚度×密度"原样保留 |
| 加工费用项可编辑 | `process_fees` + `cabinet_process_fees` | 费用项字典化（可扩展），箱柜级费用独立成表明细 |
| 成本实时重算 | 不落库 | 总成本由前端按 BOM+单价实时计算，与旧版一致；仅"引用到报价单"时写快照进 `quote_items` |
| 历史调价记录（待确认） | `material_price_history` | 已纳入设计 |
| 协作动态记录 | `operation_logs` + `quote_comments` | 平台级统一能力替代 |
